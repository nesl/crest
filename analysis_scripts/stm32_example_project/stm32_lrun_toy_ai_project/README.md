# STM32 LRUN Toy AI Project

This is the repo-local LRUN analysis workspace for the STM32 NUCLEO-N657X0-Q.

It mirrors the ST `Template_FSBL_LRUN` project shape:

- `FSBL/`
- `Appli/`
- `STM32CubeIDE/Boot/`
- `STM32CubeIDE/AppS/`

The committed `Debug/` trees only keep the CubeIDE-managed build recipe files
such as `makefile`, `sources.mk`, `objects.mk`, `objects.list`, and `subdir.mk`.
Compiled outputs are intentionally ignored by the repo.

## Runtime Model

This toy LRUN project now supports only the unattended `dev_boot` analysis
flow. Its value is the LRUN `AppS` memory layout, which exposes about `2047K`
of linker-visible runtime RAM at `0x34000400` for the TinyODOM app. It is not
meant to validate a deployment-style external-flash boot chain.

The supported flow is:

- signed `Appli` image is programmed to external flash at `0x70100000`
- optional external weights blob is programmed at `0x71000000`
- `FSBL` ELF is debug-loaded into RAM
- `FSBL` copies the trusted app into AXISRAM and jumps to it

The previous manual external-flash validation variant was removed because it required manual
BOOT strap changes and reset sequencing, which is not usable for unattended
NAS/HIL loops on the stock board.

## Workspace Layout

The workspace includes ST-derived files plus TinyODOM-specific overlays.

- `FSBL/` and `STM32CubeIDE/Boot/` come from the ST LRUN template, with local
  path adjustments for repo-contained builds.
- `Appli/` carries the TinyODOM toy AI runtime.
- The ST Edge AI `network*` files and `toy_ai_phase_config.h` are staged
  artifacts generated by the LRUN analysis scripts and are intentionally not
  committed.
- `Drivers/` and `Middlewares/` carry the STM32CubeN6 subsets needed for the
  repo-local LRUN build.
