Title: Harness-First HIL with Protocol Abstraction (Arduino Today, STM-Ready Tomorrow)

Summary
When training.energy_aware is true, HIL always uses a BLE33 harness board to power/read INA228 and report energy + harness timing. The DUT never touches INA228. A serial handshake (PING/READY/ARM/START/DONE) and D2 trigger enforce synchronization across arena sweeps and re-flashes. Host code reads DUT and harness serial ports independently with explicit timeouts and a per-attempt barrier. The handshake and parsing live in a device-agnostic protocol layer so future DUTs (e.g., STM) only need to implement the same UART+GPIO contract.

6. Host-Side Handshake (Device-Agnostic) [DONE]
Per-attempt sequence (protocol layer): [DONE]
1. [First attempt only] flash harness (if enabled), wait 500ms [DONE]
2. Flush harness serial buffer [DONE]
3. PING -> wait HARNESS READY (ready timeout) [DONE]
4. ARM -> wait ARMED (arm timeout) [DONE]
5. [If DUT needs upload] flash DUT [DONE]
6. Open DUT serial immediately; flush buffer [DONE]
7. Wait for DUT READY [DONE]
8. START [DONE]
9. Read DUT until timer output [DONE]
10. Read harness until DONE (done timeout + active timeout) [DONE]
11. Validate runs match [DONE]
12. If mismatch/timeout -> warn, energy/harness timing = -1 [DONE]
13. Close DUT serial [DONE]
14. Repeat from step 2 for next attempt [DONE]
